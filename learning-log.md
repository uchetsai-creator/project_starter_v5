# Learning Log

Personal, append-only. Not part of the document matrix in `templates/init/document-matrix.md`
— never Required or Optional for any project type, never exported to the spec PDF, never
checked by any validator. This file exists for the person doing the work, not for
stakeholders reading `docs/`.

**When to append an entry** — at Learning Checkpoint C.4 (Teach-back, see
`guidance/learning-checkpoints/common.md`), if you could not explain the change back
cleanly, or explained it wrong. Skip the entry when teach-back went fine — this file
tracks gaps, not a transcript of every task.

**Patterns line** — whenever Checkpoint A/B/C names a design pattern (or explains why
one was considered and rejected), add it here too, even on entries that otherwise have
no gap. The point is a personal roster of patterns you can recognize on sight, built up
across tasks instead of forgotten between them.

**Review cadence** — every 3rd entry, stop and re-read the previous ones before
continuing (same trigger count `sprint-change-log.md` uses for Sprint Documentation
Sync, applied here to recall instead of doc sync). Pick one older entry, and check
whether you can now explain it without looking at the notes. Mark it below if you can.
